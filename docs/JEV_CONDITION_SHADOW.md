# Jev 条件核验旁路 v1

## 边界

这是报告生成后的影子对照，不是分析师、风控或交易模块。原有 Jev 报告复核配置独立，保持关闭；新功能不写入报告正文、structured_summary、decision、任务结果或模型上下文，不触发补数或重分析。

报告和任务结果持久化成功后，只排入一个有界后台任务。该任务读取已保存报告，写入独立的 `jev_condition_checks` 集合；主流程不等待 Jev。进程内最多4个待处理任务，超限只记录警告，原报告仍完成。旁路总处理上限25秒（失败落盘最多再2秒），单次外部请求默认8秒，不重试。进程退出可能使记录停留 running，读取时标为 incomplete，不自动重发或补账。

## 开关

管理员入口：**系统设置 → 系统配置 → 配置管理 → Jev 条件核验**。默认关闭。

1. 仅开启“启用条件核验”并保存：只记录本地对照，不调用模型。
2. 还需开启“允许向 Jev 外发核验”，确认外发范围和费用提示后保存，才允许真实调用。后端可复用已有 `jev_review.json` 的密钥，不向浏览器返回密钥，也不启用旧版复核。
3. 可设置全系统每日尝试上限（1–200）；保存后针对新分析生效，不补跑历史报告。关闭总开关时外发开关同步关闭。

管理接口 `GET/PUT /api/config/jev-conditions` 均限管理员。配置保存在私有文件，以独立文件锁、版本冲突检查和原子替换防止并发覆盖。读取异常不显示为默认关闭；保存失败不显示为已生效。界面不允许更换接收方或修改密钥。

手工运维方式仍保留：

复制 `config/jev_conditions.example.json` 为私有 `config/jev_conditions.json`（后者被 Git 忽略）。不要把密钥写入本文或版本库。

- `enabled=false`：完全关闭，不创建旁路记录、不外发。
- `enabled=true, external_calls_enabled=false`：仅验收脱敏输入、规则基线和记录链路，不调用模型；结果标 not_called，不能称为 Jev 已核验。
- 两项均 true 且填写独立 api_key：才允许调用。首次生产启用须确认外发范围和额度。
- `mode` 只允许 shadow，不存在 enforce 模式。固定模型默认 jev-1.13.0；返回版本不同拒收，避免静默版本漂移。
- 每次后台任务读取配置、发送前再检查；关闭阻止新发送。已发出的请求可能完成并产生费用，但仍不影响裁决。无历史自动补跑。
- 默认每天最多20次尝试（北京时间，全用户共用原子 Mongo 计数），上限可配1–200。失败也消耗尝试名额，防止反复收费；这不是金额保证或上游价格估算。

## 输入与三字段

固定发送到 `https://api.typesafe.ai/v1/systemone`，不跟随重定向、不继承代理环境。使用 TypeSafe 官方 choice 协议；协议参考 https://docs.typesafe.ai/api 。

只接受6位股票代码、分析日、明确的 short/medium/long 周期，以及白名单报告的脱敏片段。普通片段每份最多5000字节，最终裁决最多30000字节，总 state 最多48000字节。删除个人持股、成本、账号、凭据、网络地址等所在行。任何删行、截断、缺计划/证据或超预算都在本地停止外发，记录材料不足；绝不因脱敏删掉前提而判条件满足。原报告不受此门禁影响。

每次针对整个计划中的备选入场方案核验，不混用不同方案的前提：

1. `condition_status`：met / not_met / insufficient_evidence。met 要求至少一个完整备选方案的全部前提有同周期、同时点证据；not_met 需要每个备选方案均有明确不满足证据。缺数据不是条件失败。
2. `evidence_conflict`：present / not_evident / unknown。同日期、同口径才可判断冲突；not_evident 不是事实核验通过。
3. `reason_codes`：枚举代码列表。v1通过一个 choice 返回一个主要原因，再包装为单元素列表，不宣称穷尽全部原因。

三个字段之外的服务元数据单独保存：请求/实际模型版本、输入及哈希、完整问题模板、有效的概率分布和用量、耗时、失败状态。置信度不是胜率。结构合法也不证明判断正确；互相矛盾的三字段拒收。

## 对照与读取

独立记录包含原系统动作（仅本地留存、不外发）、Jev结果及纯规则基线。v1规则基线只检测输入完整性，复杂自然语言前提保持 insufficient_evidence；不伪装成已经完成策略回测。旧报告的最终动作仅作参考，与条件满足不是同一指标，不能计算简单“动作一致率”当准确率。

所有者鉴权的只读接口：`GET /api/reports/{analysis_id}/condition-check`。未启用、记录尚未建立、无归属权限统一404；不会因查询触发调用。数据库记录仅在原报告仍归属于当前用户时可读。

报告详情新增“Jev 条件核验（仅供对照）”独立卡片，不写入正文或导出报告。仅有效 completed 记录显示三个核验字段；未调用、跳过、失败、中断和处理中分别说明，不把本地规则判断冒充 Jev 结论。卡片展示原系统动作及调用/模型/时间元数据，不展示发送材料、密钥或概率胜率。无记录不推断当前开关状态；“刷新记录”只有 GET，无自动轮询、补跑或外部调用。读取失败不阻塞原报告，切换报告/卸载时取消旧请求并忽略过期响应。

每份报告、每个策略版本只写一条记录，重复保存/并发处理以实际报告ID去重；不自动重试未完成或错误记录。换策略版本可用于以后新报告，但当前没有历史重放任务。
