# 分析失败后的恢复

失败任务详情提供「重试并复用报告」。这会创建一个关联的新任务，保留原任务及其错误记录；不是将失败任务直接改成成功。

## 恢复边界

- 仅可恢复本人失败的任务。
- 仅复用分析日期与当前北京时间日期一致的完整分析师报告；跨日期需重新分析。
- 报告来自服务端持久化的 `report_ready` 事件。优先最新事件，失败占位和被截断的正文不可复用。
- 客户端不能上传或覆盖复用正文。后端 `SingleAnalysisRequest` 用私有属性传递经验证的快照。
- 只补跑缺失或失败的分析师；研究辩论、风险评估和最终判断重新执行。
- 复用报告保留原数据时点，最终报告附「分析恢复记录」。这不等于全量实时重分析。
- 对同一原任务重复点击会打开同一个恢复任务，不重复创建；若恢复任务再次失败，可从该恢复任务继续。

## 自动重试

OpenAI SDK 内层重试关闭，请求重试由应用层统一控制，使用模型配置中的次数（安全上限 10 次）。基础分析阶段如遇暂时性模型故障，在本轮结束后允许该失败分析师单独补跑一次，补跑时不再嵌套请求重试。成功的其他分析师不重算。

鉴权错误、输入超限和明确的账号额度耗尽不做盲目网络重试。上下文超限仍由原有压缩流程处理。网关额度或连通性问题需在网关侧恢复，本功能不修改模型、账号或密钥。

## 质量保护

任一必要报告缺失或生成失败仍会终止任务，不生成投资建议。长篇模板中的明确「目标证券无法识别」同样视为失败，不能以正文长度掩盖。引擎统一通过 `get_symbol()` 兼容 `symbol` / `stock_code`，空代码在状态初始化时拦截。

多空和风控辩论每轮结束即检查各方结果；本轮失败不再进入下一轮或裁决。并行模式会等待已发出的本轮请求结束，不会撤销已消耗的额度。失败正文与轮次记录保留经过归类的原因（例如 `usage_limit_reached`），用户提示不直接回显网关原始响应或密钥。

实时报告面板按事件序号更新同一报告：补跑成功可替换失败占位，加载旧回放不会覆盖新正文。复用事件显示原数据时点提示，并标记节点完成。

## API

`POST /api/analysis/tasks/{task_id}/retry`，需正常用户认证及 CSRF 校验。

成功响应包含 `task_id`、`existing`、`reused_report_keys`。无权访问返回 404；不符合恢复条件或并发创建返回 409。创建阶段通过数据库短租约抑制并发重复提交。
